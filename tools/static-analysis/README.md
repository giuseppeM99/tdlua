# TDLua static analysis

The compilation database is generated by CMake. Keep a separate build
directory for each backend, Lua ABI, compiler and sanitizer configuration; do
not merge databases from different configurations.

Configure and build TDLua first so generated native codec headers exist. Then
run the checker against that exact build directory:

```sh
cmake -S . -B build-json-lua55 -DCMAKE_BUILD_TYPE=Debug \
  -DTDLUA_BACKEND=json -DTDLUA_LUA_VERSION=5.5
cmake --build build-json-lua55 --target tdlua
python3 tools/static-analysis/run-clang-tidy.py \
  --build-dir build-json-lua55 --expect-backend json
```

For native, use its own configured build and complete code generation before
analysis:

```sh
cmake --build build-native-lua55 --target tdlua
python3 tools/static-analysis/run-clang-tidy.py \
  --build-dir build-native-lua55 --expect-backend native
```

The runner checks that the CMake cache matches the requested backend and source
checkout, selects only translation units under `src/`, and applies diagnostics
only to TDLua `src/` and `include/tdlua/` headers. It excludes tests, TDLib,
`compat-5.3`, generated shards and build-tree translation units. Native
generated include paths must already exist. Warnings are written to
`<build-dir>/clang-tidy-report.txt`; warnings are informational and do not
fail the command, while a missing tool, invalid database, absent generated
headers or analyzer execution error does fail it.

clangd uses the same compilation database. Select a configuration explicitly:

```sh
clangd --compile-commands-dir=build-json-lua55
```

Check explicitly selected files, or changed production files relative to a
branch without rewriting them:

```sh
python3 tools/static-analysis/check-clang-format.py src/binding/client.cpp
python3 tools/static-analysis/check-clang-format.py \
  --changed-from origin/master --diagnostic
```

The diagnostic option reports legacy/style differences but does not fail on
them. Tool/configuration errors remain failures. Format only selected files
after reviewing their diff; do not run a repository-wide formatter.

For Clang Static Analyzer, configure a fresh Clang build using an external
TDLib package, then run:

```sh
CC=clang CXX=clang++ cmake -S . -B build-clang-json-lua55 \
  -DTDLUA_BACKEND=json -DTDLUA_BUNDLED_TDLIB=OFF \
  -DCMAKE_PREFIX_PATH=/path/to/tdlib -DTDLUA_LUA_VERSION=5.5
tools/static-analysis/run-scan-build.sh build-clang-json-lua55
```

The helper refuses bundled TDLib builds so the analysis does not clean or
recompile TDLib. Native analysis additionally needs the pinned schema and
host-side codegen artifacts required by the native CMake path. Clang-tidy's
`clang-analyzer-*` checks are available directly on existing GCC or Clang
compilation databases; scan-build requires a Clang-configured build.

The initial check set is diagnostic only. Record the tool version and report,
fix new high-confidence TDLua findings separately, and only consider a
blocking CI policy after a warning baseline has been reviewed.
